## 1. Vision & Stratégie Marketing

### 1.1 Mission & Vision

**Mission :**
> Rendre la progression en escalade plus intelligente, plus saine et plus collective — grâce à la technologie responsable.

**Vision :**
> L'escalade est plus qu'un sport : c'est un mode de vie. WAC veut connecter les grimpeurs entre eux et avec eux-mêmes.

**Promesse :**
Des bracelets connectés sans écran, légers et robustes, et une application dédiée à l'analyse de performances, la prévention des blessures, au partage, au challenge et à l'entraînement.

### 1.2 Les 4 Valeurs Fondamentales

**À TOUJOURS respecter dans tous les contenus :**

1. **PARTAGE**
   - Créer une vraie communauté
   - Pas juste des likes, mais du lien réel
   - Des grimpeurs qui s'entraident, se challengent et progressent ensemble

2. **ACCESSIBILITÉ**
   - Jamais élitiste ni technocratique
   - Pour tous les niveaux (5c à 8b+)
   - Pour tous les genres, morphologies, handicaps

3. **PERFORMANCE RESPONSABLE**
   - Progresser sainement, sans se détruire
   - Prévenir les blessures
   - Écouter son corps, respecter ses cycles
   - La performance, oui — mais durable

4. **TRANSPARENCE**
   - Sur nos choix techniques, notre fabrication, nos valeurs
   - Sur nos limites aussi
   - Nous ne sommes pas parfaits, mais nous sommes honnêtes

### 1.3 Les 3 Piliers Stratégiques

**À TOUJOURS mettre en avant :**

#### Pilier 1 : ÉCO-CONCEPTION 🌱
- Matériaux recyclés et réparabilité maximale
- Fabrication locale pour réduire notre empreinte
- Hébergement green de nos serveurs
- Adhésion 1% for the Planet

**Message clé :** *"Parce qu'on grimpe dans la nature, on la protège."*

#### Pilier 2 : PRÉVENTION 🛡️
- Prévention des blessures (tendinites, poulies, coiffe des rotateurs)
- Préservation de l'environnement (sites d'escalade)
- Promotion des bonnes pratiques en salle

**Message clé :** *"Progresser sans se détruire, ni détruire."*

#### Pilier 3 : INCLUSIVITÉ 🌈
- **1ère app escalade à analyser l'impact des cycles menstruels** sur les performances
- Prise en compte de tous les genres, morphologies et handicaps
- Personnalisation des analyses pour chaque profil

**Message clé :** *"L'escalade pour tous, vraiment."*

### 1.4 Ton de Voix & Ligne Éditoriale

**Caractéristiques du ton WAC :**

✅ **À FAIRE :**
- **Accessible** : jamais technocratique, vulgariser sans simplifier
- **Inspire confiance** : on parle vrai, on ne survend pas
- **Engagé** : tech utile et progression durable
- **Esprit grimpeur** : collectif, humble, passionné
- **Tutoiement** : créer de la proximité
- **Phrases courtes** : impact et clarté
- **Émotionnel** : raconter des histoires, créer du lien

❌ **À ÉVITER :**
- Ton corporate ou institutionnel
- Jargon technique non expliqué
- Superlatifs excessifs ("le meilleur", "révolutionnaire", etc.)
- Élitisme ou culture de la performance toxique
- Comparaison avec d'autres grimpeurs
- Langage genré (privilégier l'écriture inclusive avec · )

**Sources d'inspiration :**
- Patagonia (engagement moral)
- RedBull (performance inspirante)

### 1.5 Messages Clés à Retenir

**À répéter régulièrement :**

> "WAC, c'est l'histoire d'un bracelet né sur un mur d'escalade, pas dans un bureau de R&D."

> "Grimper pour se dépasser, pas pour se comparer."

> "Nos choix ne sont pas les plus simples, mais ils sont les plus justes."

> "La vraie performance, c'est la progression."

> "Et la vraie progression, c'est celle qu'on construit ensemble, dans la durée."

### 1.6 Éléments Différenciants

**À TOUJOURS mettre en avant :**

1. **Bracelet sans écran** : ne distrait pas de la grimpe
2. **Cycles menstruels** : première app escalade à les prendre en compte
3. **Prévention des blessures** : pas juste de la performance
4. **Éco-conception** : tech responsable
5. **Communauté réelle** : pas juste des likes

### 1.7 Timeline Projet

- **Q1 2026** : Beta testing avec la FFME
- **Avril-Mai 2026** : Campagne de crowdfunding
- **Statut actuel** : Application à 80% de complétion

## 2. Charte Graphique & Design

### 2.1 Palette de Couleurs

#### Couleurs Primaires

```css
--color-primary-green: #265335
/* Usage : Logo, titres principaux, textes importants, backgrounds sombres */

```

#### Couleurs Secondaires

```css
--color-secondary-orange: #F67931
/* Usage : CTA, accents, éléments à mettre en valeur */
/* RGB: 246, 121, 49 */
/* CMYK: 0, 51, 80, 4 */

--color-secondary-beige: #B19580
/* Usage : Nuances, variantes de backgrounds */
/* RGB: 177, 149, 128 */
/* CMYK: 0, 16, 28, 31 */

--color-secondary-beige-light: #E6D5C7
/* Usage : Backgrounds alternatifs, sections */
/* RGB: 230, 213, 199 */
/* CMYK: 0, 7, 13, 10 */
```

#### Règles d'Utilisation des Couleurs

✅ **À FAIRE :**
- Utiliser le vert pour établir autorité et confiance
- Utiliser l'orange UNIQUEMENT pour les CTA et accents
- Respecter le contraste texte/fond (WCAG AA minimum)
- Utiliser les beiges pour créer de la chaleur

❌ **À ÉVITER :**
- Utiliser l'orange comme couleur dominante d'une section
- Mélanger plus de 3 couleurs sur une même section
- Utiliser du noir pur (#000000) - préférer le vert foncé
- Utiliser du blanc pur (#FFFFFF) - préférer le beige clair

### 2.2 Typographie

#### Titres : Syne

```css
font-family: var(--font-syne);
font-weight: 700; /* Bold uniquement */
text-transform: uppercase; /* TOUJOURS pour les titres */
letter-spacing: -6%; /* Pour les très gros titres uniquement */
```

**Règles d'usage :**
- TOUJOURS en majuscules
- TOUJOURS en gras (700)
- Interlettrage resserré (-6%) UNIQUEMENT pour les titres > 48px
- Couleur : vert principal ou beige (selon le fond)

**Tailles recommandées :**
- H1 : 4xl (36px) à 7xl (72px) selon le device
- H2 : 3xl (30px) à 5xl (48px)
- H3 : 2xl (24px) à 4xl (36px)

#### Textes courants : Roboto

```css
font-family: var(--font-roboto);
font-weight: 400 | 500 | 700; /* Regular, Medium, Bold */
text-transform: none; /* Minuscules avec casse naturelle */
line-height: 1.6; /* 160% de la taille de police */
```

**Règles d'usage :**
- En minuscules avec casse naturelle
- Interlignage 160% (1.6) pour le confort de lecture
- Graisse variable selon hiérarchie (400 → 500 → 700)

**Tailles recommandées :**
- Corps de texte : base (16px) à lg (18px)
- Sous-titres : lg (18px) à xl (20px)
- Légendes : sm (14px)

### 3.4 Animations AOS

**Configuration globale :**

Le composant `AOSInit.tsx` initialise AOS avec :

```tsx
AOS.init({
  duration: 800,
  once: true,
  offset: 100
});
```

**Animations disponibles :**

```tsx
// Fade up (le plus utilisé)
<div data-aos="fade-up">Contenu</div>

// Avec délai pour effet cascade
<div data-aos="fade-up" data-aos-delay="100">Contenu 1</div>
<div data-aos="fade-up" data-aos-delay="200">Contenu 2</div>
<div data-aos="fade-up" data-aos-delay="300">Contenu 3</div>
```

**Règles d'usage des animations :**

✅ **À FAIRE :**
- Utiliser `fade-up` comme animation par défaut
- Créer des délais en cascade (0ms, 100ms, 200ms, 300ms)
- Animer les titres de section
- Animer chaque carte dans une grille
- Animer les blocs de contenu importants

❌ **À ÉVITER :**
- Trop d'animations différentes (rester cohérent)
- Délais trop longs (max 300-400ms)
- Animer de petits éléments (textes courts, icônes seules)
- Animations sur le hero (doit être immédiatement visible)

**Pattern standard pour une section :**

```tsx
<section className="py-20">
  <div className="container-custom">
    {/* Titre animé */}
    <h2 className="text-4xl mb-12" data-aos="fade-up">
      TITRE DE SECTION
    </h2>

    {/* Grid avec cascade */}
    <div className="grid md:grid-cols-3 gap-8">
      <div data-aos="fade-up" data-aos-delay="0">
        {/* Carte 1 */}
      </div>
      <div data-aos="fade-up" data-aos-delay="100">
        {/* Carte 2 */}
      </div>
      <div data-aos="fade-up" data-aos-delay="200">
        {/* Carte 3 */}
      </div>
    </div>
  </div>
</section>
```

### 3.5 Responsive Design

**Breakpoints Tailwind (par défaut) :**

```css
sm: 640px   /* Tablettes portrait */
md: 768px   /* Tablettes landscape */
lg: 1024px  /* Desktop */
xl: 1280px  /* Large desktop */
```

**Règles responsive :**

✅ **À FAIRE :**
- Mobile-first approach (styles de base pour mobile)
- Tester sur 3 tailles : mobile (375px), tablet (768px), desktop (1440px)
- Adapter les tailles de typo : `text-2xl md:text-4xl lg:text-5xl`
- Adapter les paddings : `py-12 md:py-20 lg:py-32`
- Adapter les grids : `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`

**Patterns courants :**

```tsx
{/* Titres */}
<h1 className="text-4xl md:text-6xl lg:text-7xl">

{/* Espacements sections */}
<section className="py-12 md:py-20 lg:py-32">

{/* Grids */}
<div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-6 md:gap-8">

{/* Flex direction */}
<div className="flex flex-col md:flex-row gap-4">
```

### 3.6 Images & Assets

**Formats préférés :**
- **Photos** : JPG (compression 80-85%) ou WebP
- **Logos/Icônes** : SVG (vectoriel) ou PNG avec transparence
- **Vidéos** : MP4 (H.264), max 5MB pour vidéos de fond

**Optimisation :**
- Utiliser `next/image` pour toutes les images
- Fournir les attributs `width`, `height`, `alt`
- Utiliser `loading="lazy"` pour images hors viewport
- Compresser avant upload (TinyPNG, Squoosh)

**Exemple :**

```tsx
import Image from 'next/image'

<Image
  src="/image.jpg"
  alt="Description précise de l'image"
  width={1200}
  height={800}
  loading="lazy"
  className="rounded-lg"
/>
```

### 3.7 Performance

**Règles de performance :**

✅ **À FAIRE :**
- Utiliser les composants serveur (RSC) par défaut
- Lazy load les composants lourds
- Minimiser le JavaScript côté client
- Optimiser les images (formats modernes, compression)
- Utiliser les fonts en local (déjà fait avec next/font/google)

❌ **À ÉVITER :**
- Librairies externes inutiles
- Images non optimisées
- Re-renders inutiles (mémoïsation si nécessaire)
- Trop de client components

**Objectifs de performance :**
- **Lighthouse Score** : > 90
- **First Contentful Paint** : < 1.5s
- **Time to Interactive** : < 3.5s

## 6. Accessibilité

### 6.1 Contraste

**Ratios minimaux (WCAG AA) :**
- Texte normal : 4.5:1
- Texte large (>18px ou >14px bold) : 3:1

**Vérifications régulières :**
- Vert #265335 sur beige #F5ECE5 ✅
- Beige #F5ECE5 sur vert #265335 ✅
- Orange #F67931 sur blanc ✅
- Blanc sur vert #265335 ✅

### 6.2 Navigation Clavier

✅ **À RESPECTER :**
- Tous les éléments interactifs accessibles au clavier (Tab)
- Ordre de tabulation logique
- Focus visible (outline)
- Pas de pièges au clavier

### 6.3 Textes Alternatifs

**Images décoratives :**
```tsx
<img src="decoration.jpg" alt="" />
```

**Images informatives :**
```tsx
<img src="bracelet.jpg" alt="Bracelet WAC Polar 360 porté au poignet lors d'une session d'escalade" />
```

**Icônes avec texte :**
```tsx
<span aria-hidden="true">🎯</span>
<span>Accessibilité</span>
```

### 6.4 Liens & Boutons

**Liens descriptifs :**

❌ **Mauvais :**
```tsx
<a href="/mission">Cliquez ici</a>
```

✅ **Bon :**
```tsx
<a href="/mission">Découvrir notre mission</a>
```

**Boutons vs Liens :**
- `<button>` : pour actions (ouvrir modale, soumettre formulaire)
- `<a>` : pour navigation (changer de page)

- `feat:` Nouvelle fonctionnalité
- `fix:` Correction de bug
- `style:` Changements visuels/CSS
- `refactor:` Refactoring de code
- `docs:` Documentation
- `chore:` Tâches de maintenance

Exemples :
```
feat: add animations to mission page
fix: correct button hover color on mobile
style: update hero section spacing
docs: add website-rules.md
```
